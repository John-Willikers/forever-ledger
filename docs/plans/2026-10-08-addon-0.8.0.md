`apps/server/src/planner/`) can plan from the real character: completed quests, quest log, last position, learned
flight paths, hearth (bind spot + cooldown), mount, XP needed per level, and real trip times (flights, boats /

changes; schema 9 files stay valid.

### Task 1: Addon — character state (`db.charState`)

**Files:** `addon/ForeverLedger/ForeverLedger.lua`, `addon/tests/test_state.lua` (new suite; add to `addon/tests/run.lua`),
harness stubs in `addon/tests/harness.lua` only where a test needs them (opt-in flags like `world.travelAPI = true`, so
the probe fixture census doesn't change).

`db.charState[charKey()]` (one table per character, replaced fields, never appended):

| Field                                                                      | Source (probe 0.6.0)                                                                                                                                | When                                                                    |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `level`, `xp`, `xpMax`                                                     | `UnitLevel`, `UnitXP`, `UnitXPMax`                                                                                                                  | login, level up, logout                                                 |
| `completed` (sorted quest ids), `completedAt`                              | `C_QuestLog.GetAllCompletedQuestIDs()`                                                                                                              | login, after `QUEST_TURNED_IN` (throttled to once per 10 s via C_Timer) |
| `log`: `{ id, done = { counts per objective } }`                           | `C_QuestLog.GetNumQuestLogEntries` / `GetInfo` / `GetQuestObjectives`                                                                               | logout (and login)                                                      |
| `pos`: `{ mapID, x, y, zone, subzone, at }` (x/y 0..1 rounded to 4 places) | `C_Map.GetBestMapForUnit` / `GetPlayerMapPosition`                                                                                                  | `PLAYER_LOGOUT` (also fires on /reload)                                 |
| `bind`: `{ zone, spot = {mapID,x,y}, at }`                                 | `GetBindLocation()`; spot = player position when `HEARTHSTONE_BOUND` fires (you stand at the innkeeper)                                             | login (zone), `HEARTHSTONE_BOUND` (spot)                                |
| `hearthReadyAt` (epoch seconds, 0 = ready)                                 | `C_Container.GetItemCooldown(6948)` or `C_Item.GetItemCooldown(6948)` (start, duration vs `GetTime()`) + `GetServerTime()`                          | logout                                                                  |
| `taxi`: `{ [taxiMapID] = { at, nodes = { {id, name, x, y, state} } } }`    | on `TAXIMAP_OPENED`: `GetTaxiMapID()`, `C_TaxiMap.GetAllTaxiNodes(id)` (`state` 0 current, 1 learned, 2 not learned; position on the taxi map 0..1) | `TAXIMAP_OPENED`                                                        |
| `mount`: `{ owned = n collected, mounted = bool }`                         | `C_MountJournal.GetMountIDs` + `GetMountInfoByID` (11th return isCollected), `IsMounted`                                                            | login, logout                                                           |

Plus `db.xpCurve[build][level] = UnitXPMax("player")` (shared by all characters; recorded at login and level up).

Caps: `log` ≤ 35 quests, `completed` ≤ 5000 ids, taxi ≤ 4 maps × 80 nodes. `/fl state` prints a one-line summary of
what is recorded for this character (level, #completed, bind, hearth ready in, #learned flight paths, mount) — Harlan
uses it in the in-game test.

**Tests (TDD):** login fills level/completed/bind zone/mount; `QUEST_TURNED_IN` refreshes `completed` (once per 10 s);
logout writes pos/log/hearthReadyAt (cooldown 600 s left → readyAt = now + 600); `HEARTHSTONE_BOUND` records the bind
spot; `TAXIMAP_OPENED` records nodes with state; level up writes `xpCurve`; missing APIs (bare client) record nothing

### Task 2: Addon — trips (flights, boats / zeppelins, hearths)

**Files:** `addon/ForeverLedger/ForeverLedger.lua`, `addon/tests/test_state.lua`.

`db.trips` (list, cap 300, oldest dropped): `{ kind = 'flight'|'transport'|'hearth', char, from = pos, to = pos,
startedAt, seconds, fromNode?, toNode? }`.

- **Flight:** `hooksecurefunc("TakeTaxiNode", …)` (observe only) records the destination (`TaxiNodeName(i)`, position)
  and the current node; `PLAYER_CONTROL_LOST` starts the clock, `PLAYER_CONTROL_GAINED` with `UnitOnTaxi` false (or
  after landing) ends it (probe: Org → Splintertree 89.7 s).
- **Hearth:** `UNIT_SPELLCAST_SUCCEEDED` for `player` with spell 8690 → `from` = position, clock starts; the next
  `PLAYER_ENTERING_WORLD` or a position > 200 yd away ends it.
- **Transport:** a 2 s ticker (C_Timer, only while not on a taxi): `GetUnitSpeed("player")` = 0 while the map position
  moves > 3 yd per tick → riding; ends when the position stops moving for 3 ticks or after a loading screen pair
  (`LOADING_SCREEN_ENABLED/DISABLED`) once on the far side and stopped. Keep it cheap (one position read per 2 s).

**Tests:** a flight (hook + control events) records seconds and nodes; a hearth records from/to; a transport ride
(position moving at speed 0, then a loading screen) records one trip; walking (speed 7) never records a transport;
cap 300. Commit `feat(addon): record flight, transport and hearth trips`.

### Task 5: Planner input from stored state

**Files:** `apps/server/src/knowledge/character-state.ts` (DB → planner inputs), `apps/server/src/planner/xp.ts`
(optional curve), tests.

- `loadCharacter(db, charKey): { ch: CharacterState; travel: TravelData; gaps: string[] }`:
  - `CharacterState` from `character_state` + `characters` (class token, race token, faction). `position` from `pos`
    (percent = x*100). `completed` set. `log` map. `flightPaths` = node ids with state 0/1 from every `taxi` map.
    `hearth` = `{ spot: bind.spot, readyAt: max(0, hearth_ready_at − now) }` (planner clock starts now) or null when
    the bind spot is unknown (gap "bind spot unknown: set your hearth once with 0.8.0").
  - `TravelData.flightNodes` = all nodes ever seen in any character's `taxi` (dedupe by node id; position on the taxi
    map → world via the continent map — taxi map 1464 = Kalimdor, 1463 = Eastern Kingdoms per probe; convert with
    `geo.ts`), faction from the probe's `GetTaxiNodesForMap` data where known else 'both'. `transports` from
    `planner/transports.ts`, with crossing/wait replaced by the median of recorded `trips` of kind transport whose ends
    match a transport's docks within 150 yd.
  - Flight time: if recorded flights exist, fit the detour factor (`travel.ts` constant → a parameter with default
    1.25) from their medians.
- `xp.ts`: `xpToNext(level, cap, curve?)` uses `xp_curve` for the build when present.
- Tests (DB-backed via the repo's test Postgres helper): a stored state becomes the expected `CharacterState`; nodes
  from two characters merge; a missing bind spot gives the gap; recorded trips change transport time. Commit
  `feat(planner): plan from a character's stored state`.
